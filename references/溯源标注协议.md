# 溯源标注协议（2026-08-13）

## 目的

每次处理和分析完问题后，在输出末尾只提供一个可点击入口，不完整展示来源清单。用户点开后，在 HTML 对话框中按需查看本次分析实际用到的技能包和书籍原文，完成“分析 → 技能 → 原文”的完整追溯。

## 触发范围

- 使用任何已蒸馏书籍技能完成的分析，都必须追加溯源标注。
- 未使用书籍技能的分析不强行列书；但必须在末尾注明“本次未使用书籍技能，未提供原文链路”。
- 极简版至少保留 1 个最核心来源；标准版、深度版、辩证版全部列出实际用到的来源。

## 输出格式

在分析主体和相反辩证视角之后，生成一个 HTML 对话框文件，并在对话中只输出一个可点击入口：

```markdown
## 可查技能原文

[查看可查技能原文](运行目录)
```

生成命令：

```bash
python3 skills/simaguang-perspective/scripts/build_traceability_panel.py \
  --output 运行目录/学习记录/可查技能原文/可查技能原文-<日期>-<标题>.html \
  --title "可查技能原文" \
  --sources '[{"book":"《书籍名》","skill":"运行目录/skills/书籍名/SKILL.md","source":"公开来源引用"}]'
```

若环境无法生成 HTML，改用折叠形式，不在正文展开完整列表：

```markdown
<details><summary>可查技能原文</summary>

- 技能链接：...
- 原文链接：...

</details>
```

## 路径规则

- 技能包路径优先指向 `knowledge/books/*.md`。
- 原文路径优先指向同项目的 `references/素材来源索引.md` 或 `references/素材来源索引.md`。
- 主书《资治通鉴》原文指向 `公开来源引用`。
- 早期项目位于 `其他书籍/` 时，按实际路径链接；路径不确定时必须先 `ls` 或 `find` 核验，不编造链接。
- 同一本书只列一次；同一分析中实际用到多本书时全部列出，并按使用权重排序。
- 链接使用 Markdown 可点开格式，必须使用绝对路径。

## 内容边界

- 只列本次分析实际调用的技能，不把整个知识库全部列出。
- 对话中不完整展示技能和原文清单，只显示“查看可查技能原文”入口。
- HTML 对话框按需打开；用户未点击前看不到完整来源列表。
- 技能包可以证明“判断尺来自哪本书”，原文可以证明“书里确实有相关内容”。
- OCR 文本含噪声时，在原文链接后标注“OCR 文本，需对照原书”。
- 涉及实时新闻、外部数据或非书籍来源时，单独列“外部信息待核验”，不伪装成书内原文。

## 自检

输出前检查：本次用到的每本书是否都有“技能链接 + 原文链接”；路径是否真实存在；是否有多余的未使用书；是否把分析结论误写成书内原话。

## 核验工具

每次生成可查技能原文面板后，执行：

```bash
python3 skills/simaguang-perspective/scripts/verify_traceability.py
```

该脚本检查 `运行目录/学习记录/可查技能原文/` 下所有面板，确认每个链接指向的本地文件存在且非空。任一来源路径损坏或为空，必须在交付前修复。

## 版权安全

- 原文只保存在本机，不把全书文本复制到聊天、skill、外部 agent 或公开产物。
- 对外只输出短引用、章节/页码和本地路径；不得粘贴全书或大段原文。
- 公有领域古籍可保留原典路径；有版权的现代书籍只保留“判断尺 + 短引用 + 来源元数据”，不提供全文下载或复制。
- 溯源面板链接到本地原文路径，不内嵌原文正文；需要把面板发给他人时，先检查是否包含版权文本、个人信息或非公开资料。
- 生成可查技能原文面板后，必须运行 `verify_traceability.py` 确认链接可查。
