# 主动学习补给协议（2026-08-12）

## 目的

发现短板后主动申请相关书籍、刊物、视频、音频、访谈、案例等资料，并推动“提供 → 蒸馏 → 并入 → 验证”的闭环。

## 触发条件

- 复盘发现同一短板重复出现 2 次以上。
- 用户反馈某项能力不足。
- 热点或案例分析暴露明显知识缺口。
- 能力评估显示某类判断长期低置信。

## 补给申请单字段

- 短板：具体能力缺口。
- 证据：哪次分析、哪个案例或哪条规则暴露了缺口。
- 需要补的能力：补完后能解决什么问题。
- 建议资料类型：书、刊物、视频、音频、访谈、案例集。
- 建议主题：可选书名、作者、领域或搜索方向。
- 优先级：高/中/低。
- 状态：待提供 → 已提供 → 蒸馏中 → 已并入 → 待验证。

## 补给论证（必填）

每次主动建议补充某领域知识时，必须说明：

1. 为什么是现在？
   - 哪个具体案例、分析或用户反馈暴露了当前薄弱环节。
   - 补充后，在什么具体场景会产生可见提升。
2. 预计补到什么深度？
   - 通识了解：1-2 本入门书或入门视频即可。
   - 深度精通：需要系统课程、系列著作或长期案例训练。
3. 不能及时补充会怎样？
   - 哪些类型分析会无法完成。
   - 哪些分析存在较高风险被表面信息误导。

## 输出位置

`运行目录/学习记录/补给申请/主动学习补给单-<日期>.md`

## 闭环

- 每周自动化先读取补给申请单。
- 学习循环协议会把“复盘学习日志 → 生成补充计划 → 定向蒸馏 → 前后对比”串成闭环，见 `学习循环协议.md`。
- 有新资料则按默认流程蒸馏。
- 蒸馏后更新状态为“已并入”。
- 蒸馏前先确认资料命中的短板和目标能力，定向补齐。
- 资料仍未提供时，在汇报中提醒用户。

## 边界

- 不主动下载、购买或调用付费资料。
- 只生成申请和建议，由用户确认后处理。
- 同类资料优先归簇查重，不重复蒸馏。
