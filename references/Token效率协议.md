# Token 效率协议（2026-08-11）

## 主 SKILL 与知识库加载（2026-08-19）

- 主 `SKILL.md` 只保留运行入口、协议路由和核心判断尺；新增书籍、协议或判断尺只写入 `references/` 和对应技能包，不在主 SKILL 重复展开。
- 分析时先按问题查 `references/技能合并索引.md`，按需读取 1-3 个技能包；不把整个 references 目录一次载入。
- 提取文本书籍只用于蒸馏、溯源和深度核验，不参与常规上下文加载。
- 协议和索引能合并就合并；同一能力只保留单一活动入口，旧文件归档。
- 每次改版前先跑回归基线，改版后比较 token 变化和行为是否退化。
- 新增 test-prompts 只增加真正覆盖新行为的条目，不为计数而扩充。

## 对话

- 禁止计划表达和状态铺垫；先执行，再给“结果 / 证据 / 待验证”。
- 普通回复不超过 200 字；长内容只给摘要和文件链接。
- 不重复输出项目状态、文件清单、书籍清单、节点或簇；只输出本次变化。
- 同一问题 5 分钟内直接返回缓存摘要。
- 长任务先确认后台；过程中不把进度刷给用户，只在完成或失败时汇报。
- 高资源长任务未确认后台前不得自动启动。
- 蒸馏书籍等长任务询问“是否后台进行”时，默认同意并继续执行，不再重复等待用户确认。
- 蒸馏任务开始不列“先整理/再蒸馏/再总结/再提取技能/并入司马光综合思维”步骤；后台运行不逐本刷状态，只在完成或失败时一次性汇报最终结果、关键文件和验证证据。

## 蒸馏

- 每本书或资料默认不超过 14 个判断尺；确需更多才扩展，并说明理由。
- 蒸馏必须显式调用 `cangjie-content-distill`，或说明不使用理由。
- 同簇书先归簇查重；重复尺不新建。
- 提取文本保留一份；技能包只写可执行判断尺，不重复整段原文。
- 配套文件只更新变化，不复制整份技能到多份日志。
- 不逐本输出“已整理/已蒸馏/已总结”状态；后台任务完成后一次性汇总结果。
- 低贡献书归档或压缩，不继续膨胀主技能。

## 代码 / 脚本

- 复用通用脚本，不复制每本书一份 OCR 脚本。
- 脚本默认只输出关键结果：总页数、完成进度、失败页、最终字符数。
- 不打印完整 raw 文件、完整目录树或大段日志。
- 批量处理优先；临时中间文件合并后删除。
- 新依赖要评估必要性，能用本地库就不新增。
